# 2026-10-18

Branch: `fix/search-matching`

## What was done
- Fixed the item search so a brand like H&M no longer brings up unrelated items. Eden searched "H&M" on the live site and got Tommy Hilfiger jeans and Puma shoes. The search was cutting "H&M" into the two letters "h" and "m" and accepting any item whose title or brand had those letters anywhere. Now a word keeps the marks that join it (H&M, Levi's, T-shirt, ג'ינס), the spellings with and without the mark find the same items (HM, levis, גינס), and a word of one or two letters only matches a whole word. Recorded as D-057 in `docs/design.md`.
- A whole search that only looks like a brand (a typo such as "nikee" or "zaraa") still becomes that brand, but a brand plus any extra word ("nike air", "zara xs", "תיק zara") no longer collapses into the brand alone.
- In the default order, items with every search word at the start of a word in the title or brand now come before items where the word hides inside a longer word. Searching גינס used to show a book by "היגינס" first.
- Favourites search uses the same matching as the main search.
- Tests: a new unit test file for the word splitting and new live database tests for H&M, Levi's, Hebrew geresh, single letters and the brand typo rule. 167 server search tests pass, typecheck and lint are green.
- Checked against real data: a helper ran 244 real searches (taken from the 196 live listings) against the live server and against the fixed server running on a read-only copy of those listings. Production got 43 of them wrong (junk for H&M and single letters, missing results for גינס, זקט, Hebrew prefixes, "גינס קצר", "pullbear", "sacks", brand plus word searches). The fixed code matched the expected answer on every one after the last change.

## Decisions
- D-057 (Eden asked for a battle tested search, Claude proposed the rules): search words stay whole, short words match whole words only, word-start matches rank first, a brand typo needs the same number of words. In `docs/design.md`.
