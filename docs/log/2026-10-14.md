## AI models: which one should power our smart features?

### What was done

- **Tested four AI models** on one job: fill in category, brand, condition and colour from what a seller types.
  - **Jev**, the first model from TypeSafe AI (typesafe.ai). It answers from a fixed set of choices and says how sure it is.
  - **Claude Haiku 5.5**, Anthropic's small, cheap model.
  - **GPT-6 Luna** and **GPT-5 nano**, OpenAI's cheapest models.
- **60 listings:** 30 from our sample data and 30 written to look like real sellers (slang, typos, Hebrew and English mixed, brands written in Hebrew letters). The answers were written down before the test.
- **Results:**

| | Claude Haiku | GPT-6 Luna | GPT-5 nano | Jev |
|---|---|---|---|---|
| Category | 95% | 95% | 78% | 80% |
| Category, Hebrew only | 97% | 94% | 82% | 73% |
| Brand | 97% | 95% | 67% | 98% |
| Condition | 83% | 83% | 80% | 90% |
| Colour | 100% | 100% | 87% | 97% |
| Time per listing | 1.6 sec | 1.3 sec | 2.6 sec | 0.8 sec |

- Each model cost about a cent or less for the whole test.
- **Jev** reads Hebrew fine and its "how sure" score is honest, but it is weak at categories.
- **GPT-5 nano** missed a third of the brands, even plain ones like IKEA and Canon.
- **Haiku and Luna** both missed nicknames ("MK" for Michael Kors, "PS5" for Sony).
- **Online research** (official Google and OpenAI price pages plus comparison sites): Haiku is in the cheapest price tier. At our size, cost does not separate the models. No public Hebrew comparison exists, so our own test is the evidence.
- **Nothing in the app or server changed.** The tests lived in a temporary folder outside the project. Keys for Jev and OpenAI are in the server's private settings file and nothing uses them yet.

### Decisions

- **Claude Haiku powers our AI features (Eden).** It ties with GPT-6 Luna on quality, scores best on Hebrew categories, and is already set up, so there is one company and one bill. Tracked in `docs/unfinished-work.md`.
- **Which AI features (Eden):**
  - **Yes:** search in plain words, style tags for the Home feed, photo check before publishing, quick replies in chat, chat warnings (deals moved off the app, scams), listing checks (banned items, fakes, offensive text), report sorting, help answers from our help pages, problem summaries for Eden when an order goes wrong.
  - **Potential idea, parked:** translating listings between Hebrew and English.
  - **No:** AI-written listing descriptions.
- **Lines the AI does not cross:** it never moves money, changes an order or bans anyone by itself. It suggests and warns, and a person or our fixed rules decide. Automatic text is labelled. Reading chats must be stated in the privacy policy.

### Problems and fixes

- **Our category tree has overlapping branches.** All models stumbled on the same spots, so sellers and buyers will too:
  - Running shoes sit under both Men's shoes and Sports.
  - Backpacks sit under both Men's bags and Camping.
  - Designer bags sit under both Women's bags and Designer.
- **The category list changed in the middle of the test.** Another session switched the main folder to `feat/website-w2`, which renames and expands the categories (273 became 387, commit `4e19cd5`). The first OpenAI run used the new list against an answer key written for the old one, so it looked much worse than it was. Fix: re-ran both OpenAI models on the old list. Lesson: freeze the data a test reads before starting.
