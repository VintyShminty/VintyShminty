# 2026-10-13

Branch: `milestone-4` (new, nothing built on it yet)

## What was done

- **Milestone 3 Discovery is merged** (PRs #10 and #11). In the app you can now:
  - Scroll the Home feed with the chips All, Women, Men, Trending, Designer and Kids.
  - Browse the category tiles (Designer included) and drill down through full screen category panels.
  - Search with suggestions while typing, see recent searches, and switch between an Items tab and a Members tab.
  - Open Filters as a full screen with sort and a live "Show N results" button, and save a search with the bookmark.
  - Tap a heart on any card. It fills at once and the feed no longer reshuffles under your finger.
  - Open an item as a buyer: photos, price, details, seller card, More like this, and Report in the "..." menu.
  - Visit a seller's profile, and find Favourites and Saved searches on your own Profile.
  - Pick your sizes in Settings, so the feed favours them.
- **Buy, offer and message** are left out on purpose. They come in Milestones 4 and 5.
- **How it was built:** one helper built the server side first. Then two helpers built the screens side by side, each in its own copy of the project with its own simulator. A third helper went through the screens in English and Hebrew and fixed what was off.
- **Library upgrades:** the three big upgrade suggestions (PRs #6, #7, #8) are closed. Dependabot (the robot that suggests library upgrades) now skips big version jumps. Small and safe updates and security fixes still come through.

## Problems and fixes

- **The product spec file is missing.** The folder that held it is gone from the Desktop, so the screens were built from our own design notes. A few details are guesses, for example the list of Report reasons.
- **One helper could not use its simulator.** The app asks Eden to allow control of each simulator. Once he allowed it, the screen check ran.
- **Tapping a saved search opened an empty search.** Root cause: the two halves of the app were built by different helpers, and the saved search list passed the search in a way the search screen did not read. Fixed in two steps: first the search was handed over correctly (`5819166`), then the search screen showed the results instead of the typing view (`3380764`).
- **Hebrew sentences starting with a username read in the wrong order** (for example the holiday banner). An invisible right to left mark at the start of those sentences fixed it (`a90ec57`). A wider fix on all text was tried first and broke English words inside Hebrew screens, so it was undone.
- **PR #10 was merged before the last fixes landed.** They went into a small follow up, PR #11. Lesson: say clearly in the PR when checks are still running.
