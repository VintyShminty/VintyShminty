## Security check fixed and every open PR merged

### What was done

- **Every PR can go in again.** Since main last moved on 2026-10-19, the required security check (it scans our add-on packages for known safety problems) had started failing on every PR, so nothing could be merged, PR 154 (Basta) included.
- **The live website runs Next.js 16.4.6** (Next.js is the engine the website is built on). 16.4.0 had two critical holes that let an outsider run code on the website's server (#155). Also updated: zod (checks incoming data), vite (test tool), node-forge (signing inside Expo's build tool) and Expo's command line tool, which dropped an old zod with no fix.
- **Dependabot's routine updates landed in one clean PR** (#156): sign-in (Better Auth), the server framework (fastify), email sending, data loading, translations, icons, forms, the test runner. It replaced Dependabot's #142, #143 and #148, which kept failing because the robot picked versions younger than our 7 day wait.
- **Six Dependabot PRs closed** with a note: #146, #152, #153 (replaced by #155) and #142, #143, #148 (replaced by #156).
- **All open PRs merged**, by Claude at Eden's request, in this order: #156, #154, #149, #150, #140, #134, #137, #151 (plus #155 and #157, merged by Eden). Before merging, checked that none changes the database layout or needs a new live server setting. After merging, everything on main passes the type check, code style, tests, security check, website build and server bundle, and Vercel put the server and website live.
- **Checked whether the website was hit while it ran the unsafe Next.js** (22 Oct to 17 Nov). It could not have been. The photo resizing hole needs an old sharp (the add-on that resizes photos), and we had the fixed sharp 0.35.5 since 14 Oct, with SVG pictures not allowed through resizing either. The other two holes need features the website does not use ("use cache" and server actions). Nothing to rotate. Vercel's free plan keeps only about an hour of activity records, so there were no older records to read anyway.

### Decisions

- Eden: merge everything once green, and asked Claude to do the merging this time.
- Two safety warnings accepted on purpose because no usable fix exists, each written in `pnpm-workspace.yaml` (`auditConfig.ignoreGhsas`) with the reason and a recheck date:
  - decode-uri-component inside expo-router 57: the only fixed version cannot be loaded by the older code, so forcing it would break links in the app. Goes away with Expo SDK 58. Recheck 2026-12-01.
  - picomatch (matches file name patterns, only in build and test tools on a computer): the warning names 4.0.8 as the fix but it is not released. Recheck 2026-11-24.

- Add-ons we only get through other add-ons are lifted with "overrides" in `pnpm-workspace.yaml`, each with a short reason. They only touch the unsafe versions, so they stop doing anything once the parent package moves on.

### Problems and fixes

- **Everything blocked at once.** Root cause: main stood still for a month while new warnings were published about add-ons we already had. Lesson: merge small things often and deal with Dependabot weekly, so fixes stay small.
- **A new warning landed halfway** (picomatch), right after #155 went in, and blocked every PR again. Fixed with a small PR of its own (#157) so the other PRs did not have to wait on anything bigger.
- **The version rule could not reach vite.** The test runner does not install vite itself, it expects us to bring it, and overrides do not apply to that kind of add-on. Fix: list vite directly next to vitest in each package.
- **Installs hung for minutes.** After a version change pnpm tried to download Next.js and Biome pieces built for Windows and Linux and kept retrying. Fix: write the version list first (`pnpm install --lockfile-only`), then install only what this Mac needs, with a time limit.
- **The code style check failed only on GitHub for #156.** Biome 2.6 wanted to reformat Markdown tables. Fixed by keeping Biome at 2.5.15.

## The app is now Basta, in Cobalt

Branch: `feat/basta-cobalt` (merged as #154)

### What was done

- **The name Yadii is gone, everything says Basta.** The name under the app icon on iPhone and Android, the Face ID question, the Home wordmark, the welcome screen, every email, the server's own sign in error and invite pages, the website's page titles and the preview card shown when a link is shared. The admin export file is now called `basta-uploads-<date>.xlsx`.
- **The lead colour is Cobalt blue** (#2446A8) instead of espresso brown. Buttons, prices, the Sell button and active tabs are cobalt. The cream backgrounds and borders are now a pale blue white, and text is a neutral grey instead of warm brown. The emails and the server's pages use the same colours.
- **The logo tag has a bold B** where the Y was, same tilt and string. All icons were redrawn from it: the app icon (light tag on a cobalt square), the Android icon layers, the splash screen (cobalt tag on white), the website's tab icons and the share picture.
- The website was opened on this Mac and showed the B tag, "Basta" and the cobalt Sell button. The phone app was not opened in the Simulator, no build was installed there.

### Decisions

- Eden: the new name is Basta (a market stall in Hebrew slang), replacing Yadii. Recorded in D-060 (`docs/design.md`).
- Eden: the colour is Cobalt, one of the three blues from `docs/mockups/colour-options-4.html`. Before starting, Claude checked the logs: no blue had been written down as chosen, so Eden picked it from the options. D-060.
- Eden: the logo keeps the tag with a bold B in place of the Y (other options were keeping the Y or an empty tag). D-060, D-046 marked as changed in part.
- Eden: Hebrew screens also write "Basta" in Latin letters, so the brand looks the same in both languages (other options were בסטה or באסטה). D-060.
- Claude: the faintest grey text is #736E6A, a touch darker than the mockup's, because the mockup's grey was too pale to read well on the light blue surface.

### Problems and fixes

- **The merge was blocked by the security check**, which had started failing for reasons unrelated to this change. Fixed in a separate session, see "Security check fixed" above.
- **ImageMagick (the image tool on this Mac) drew the logo as a blank picture.** Its own drawing engine cannot handle these SVG shapes. Fix: drew the logo large in Chrome without a window, then shrank it into each icon at the exact size and spot the old Y tag had.
- **The first B was too heavy.** Its holes nearly closed up at small sizes. Made it taller with rounder bowls, then checked it at favicon size (48 pixels) before using it.
- **The renaming swap also rewrote two history notes** (`docs/knowledge/decisions.md` and `glossary.md`) that record what was true on 15 October. Put back as they were. History stays as it was written.
